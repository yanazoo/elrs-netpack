# v2.7 — netpack XIAO の自動再接続

### 🐞 修正：netpack XIAO がタイマー／RotorHazard と自動で接続しない

**1. 設定用 AP から戻らない**

起動から 30 秒以内に保存した WiFi（タイマーの AP やルーター）に入れないと、netpack XIAO は設定用 AP（`ELRS-Netpack-Setup`）に切り替わります。WiFi が 60 秒以上切れたときも同じです。これまでは、その後**二度と保存した WiFi を試しませんでした**。

タイマーより先に netpack の電源を入れた場合や、タイマーがクライアントモードからホストに切り替わるのを待った場合に、つながらないままになっていました。

- WiFi を保存してある場合、設定用 AP は **AP+STA** で立ち上げ、**15 秒ごとに保存した WiFi を再試行**します。つながったら設定用 AP を閉じます
- 設定用 AP に誰かが接続している間は、設定画面の邪魔をしないよう再試行を止めます
- WiFi を保存していない（初回）場合は、これまでどおり AP のみです

**2. 新しい TCP 接続を受け付けない**

タイマーや RotorHazard が再起動すると、netpack 側には古い接続が残ります（keepalive が切るまで約 11 秒）。その間、新しい接続を受け付けていませんでした。

- 新しい接続が来たら、古い接続を閉じて新しい方に切り替えます

### ✅ 動作確認

- 実機で、netpack を先に起動 → 後からタイマーを起動、タイマーの再起動、netpack の再起動のいずれでも自動で接続することを確認しました
