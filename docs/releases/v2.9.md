# v2.9 — ESP-NOW ブリッジ：レースディレクター用の受信フィルター

### 🐞 修正：レースディレクターのスイッチが効かない・接続先への回線が混む

これまでブリッジは、チャンネル 1 で聞こえたものを**全部**接続元（ラップタイマー／netpack XIAO）に渡していました。ディレクターの送信機のスイッチだけでなく、次のものも渡っていました。

- ほかのブリッジのブロードキャスト OSD
- ほかのバックパックの通信

その結果、次の問題が起きていました。

- タイマーに UART でつないだままのブリッジや、会場にある別のブリッジの通信が、UART／TCP の回線に流れ込んでいた
- ブリッジがパイロットの UID にいる間に聞こえたパイロット自身の DVR スイッチと、ディレクターの操作を区別できなかった

### 🔧 変更

- **受信フィルター（独自 MSP `0x0F01`）**
  - 接続元がディレクターの UID（6 バイト）を送ると、ブリッジはその UID **から**届いたフレームだけを渡します。
  - ブリッジは `0x0F01`（ペイロード `1`）で応答します。
  - ペイロードを空にすると解除します。
  - これを送らない接続元（RotorHazard の vrxc_elrs）には、これまでどおりすべて渡します。
- **受信キュー**：ESP-NOW で受け取ったフレームはいったんキューに入れ、`loop()` から UART に書き出します。WiFi のタスクが UART の書き込みを待たなくなります。
- Arduino-ESP32 3.x でビルドしたときに出ていた警告（`volatile` の `++`）を解消しました。
- README（日本語）に、v2.8 の送信方式と WiFi チャンネルの推奨を追記しました。

### ✅ 動作確認

- PC 上で、本物の `src/main.cpp` を ESP-NOW / UART のスタブとつないで動かしました。
  - フィルターなしではすべて転送する
  - フィルターを設定すると応答が返る
  - パイロットの UID から届いたフレームは転送しない
  - ディレクターの UID から届いたフレームは転送する
  - 大量に届いても止まらない
  - OSD は従来どおり 3 回送る
- Wrover-E と XIAO ESP32-C3 のビルドを、CI（FPV C5 Lap Timer）と実機で確認しました。
- 実機で、netpack 経由と UART 直結の両方で、ディレクターのスイッチが効くことを確認しました。
