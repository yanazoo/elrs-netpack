# v2.5 — XIAO ESP32-C3 をブリッジに対応・応答しないゴーグルでの送信詰まりを解消

### ✨ 追加：ESP-NOW ブリッジに Seeed Studio XIAO ESP32-C3 を使えるように

ESP32 Wrover-E の代わりに、小型の **XIAO ESP32-C3** を ESP-NOW ブリッジとして使えるようになりました。ソースは共通で、PlatformIO の環境 `xiao_esp32c3` を選ぶだけです。

| ブリッジ用ボード | 環境 | UART（ホスト側と TX/RX を交差） |
|---|---|---|
| ESP32 Wrover-E | `esp32dev` | GPIO26 = RX、GPIO27 = TX |
| XIAO ESP32-C3 | `xiao_esp32c3` | D7 / GPIO20 = RX、D6 / GPIO21 = TX（Serial1） |

- XIAO C3 のログは USB シリアル（115200bps）に出ます
- XIAO C3 は付属の外部アンテナを必ず接続してください

### 🐞 修正：ゴーグルを使っていないパイロットがいると OSD の行が消える・ちらつく

電源が入っていない・範囲外のゴーグル宛てのパケットは ACK が返らないため、1 パケットごとに再送を使い切っていました。その間、次のパイロットへの送信と UID 切り替えが大きく遅れ、16 個の TX キューがあふれて、**ゴーグルが動いているパイロットの行まで捨てられていました**（レースクロックでパイロットごとに毎秒送信されるため、ちらつきとして見えます）。

- ある宛先へのパケットが再送しても失敗したら、**そのバーストの残りを飛ばす**ようにしました。次の SET_SEND_UID で改めて送信を試みます（ログ：`[espnow] skipped N packets to unreachable goggles`）
- TX キューを **16 → 48** に拡大
- UID 切り替え時のキュー掃き出し待ちを 60 → 200 ms、UART 受信バッファを 2 KB → 4 KB に拡大

### ✅ 動作確認

- Wrover-E（`esp32dev`）・XIAO ESP32-C3（`xiao_esp32c3`）の両方のビルドを [FPV C5 Lap Timer](https://github.com/yanazoo/FPV-C5-Lap-Timer) の CI で確認しました
- XIAO ESP32-C3 をブリッジにして、FPV C5 Lap Timer（UART 直結）からゴーグルへの OSD 表示を実機で確認しました
- 送信詰まりの対策（バーストの残りを飛ばす処理）は、実機ではまだ確認していません
