# v2.8 — ESP-NOW ブリッジをコネクションレス送信に（OSD の遅れ・秒飛びの解消）

### 🔧 変更：ESP-NOW ブリッジの送信方式を UDP のようなコネクションレスに

これまでブリッジは、パイロットの UID 宛てに個別送信し、ゴーグルからの受信確認（ACK）を待って、届かなければ最大 3 回送り直していました（TCP に近い方式）。現場では次の問題がありました。

- 電源の入っていないゴーグル（最大 8 台）は返事をしないので、その待ち時間と再送で、電源の入っているゴーグルの OSD まで遅れたり、レースクロックの秒が飛んだりしていました
- 同じバインドフレーズのゴーグルが 2 台とも電源オンだと、返事同士がぶつかって失敗扱いになり、再送が増えていました

新しい方式：

- ブリッジの MAC は今までどおりパイロットの UID です（ゴーグルは、その UID から来たパケットだけを表示します）。宛先は **ブロードキャスト** にし、受信確認を待たず、再送もしません
- 1 人分の画面更新（次の宛先指定まで、または 20 ミリ秒送信が途切れるまで）を、続けて **3 回** 送ります
- 同じパケットのコピー同士は **最低 3 ミリ秒** あけます。各パイロットの ELRS 2.4GHz 送信機は数ミリ秒ごとに周波数を変えるので、少し後のコピーは別の周波数のタイミングに当たり、届きやすくなります
- 電源の入っていないゴーグルがいくつあっても、他のパイロットの表示は遅れません。同じバインドフレーズのゴーグルは 2 台とも同じ表示になります
- 長めの電波の途切れは、送信元（ラップタイマー、RotorHazard の vrxc_elrs）の時間差の再送で補います
- UID 切り替えのたびに出していたログは止めました（loop() を止めて OSD を遅らせていたため）。調べるときは `-DBRIDGE_VERBOSE` を付けてビルドしてください

### 📝 ドキュメント

- README に送信方式の説明を追加しました
- netpack の XIAO が接続するルーターは、2.4GHz の **チャンネル 6〜11** を推奨します（ESP-NOW はチャンネル 1 固定のため）

### ✅ 動作確認

- 実機で、他のパイロットのゴーグルに表示が混ざらないこと、電源の入っていないゴーグルが混ざっていてもレースクロックが遅れないことを確認しました
- Wrover-E・XIAO ESP32-C3 のビルドを CI（FPV C5 Lap Timer）で確認しました
