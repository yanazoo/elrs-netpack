# ELRS-NETpack v2.3.1 — ホストモードの安定化 / Steadier host mode

> **Language / 言語:** [日本語](#日本語) | [English](#english)

<a name="日本語"></a>

## 日本語

### 変更

- **FPV C5 Lap Timer の見分け方**：FPV C5 Lap Timer として覚える機器（台数制限で必ず入れる 1 台）を、FPV C5 Lap Timer 自身の MSP 接続からだけ覚えるようにしました。以前は RotorHazard など TCP 8080 につないだ機器も覚えてしまい、本物の FPV C5 Lap Timer がスマホ・PC として数えられ、台数が上限のときに切られることがありました。
- **ホストモードの空き**：アクセスポイントの上限を「スマホ・PC の台数＋2」にしました（台数の制限は今まで通り）。FPV C5 Lap Timer がいったん切れてつなぎ直すとき、上限を超えたスマホを切る前でも入れるようにするためです。FPV C5 Lap Timer をまだ覚えていない間は、合わせて「スマホ・PC の台数＋1」台までです。
- **TCP キープアライブ**：約 11 秒（5 秒＋2 秒×3）から 約 22 秒（10 秒＋3 秒×4）にしました。電波が弱いときに、確認が数回届かないだけで FPV C5 Lap Timer との接続を切っていました（FPV C5 Lap Timer が WiFi から離れたときは今まで通りすぐに切ります）。

### 動作確認

- ビルドを確認しました。FPV C5 Lap Timer v2.3.4 と合わせて、実機での確認をお願いします。

## English

### Changes

- **Knowing FPV C5 Lap Timer**: the device kept a place under the device limit is learnt only from FPV C5 Lap Timer's own MSP session. RotorHazard (or anything on TCP 8080) used to be learnt instead, and the real timer was then counted as a phone and sent off when the phones were at the limit.
- **Room in host mode**: the access point takes phones / PCs + 2 (the limit itself is unchanged), so FPV C5 Lap Timer rejoining after a drop is never turned away while a phone past the limit is still being sent off. Until the timer is known, phones / PCs + 1 in all.
- **TCP keepalive** ~22 s (10 s + 3 × 4 s) instead of ~11 s: a few lost probes on a weak link dropped the timer's session (the timer leaving the WiFi still ends it at once).

### Verified

- Builds. Please check on hardware with FPV C5 Lap Timer v2.3.4.
